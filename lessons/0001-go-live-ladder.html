Three paths, one process

Same FastAPI app. Same router/auto. The env var only changes which Decision is served:

  • off — today’s rules (learned stub only if its own flag is on).
  • shadow (default, including invalid values) — client gets the rules model; JSONL and X-Router-Trained-Would record the trained would-be.
  • trained — client gets the cheapest eligible model that clears effort threshold and max_regret.

If the Scorer file is missing, shadow and trained both degrade to rules with reason_code scorer_down and no Confidence header. That is intentional: a forgotten data/scorer.json must not fabricate probabilities.

Do rung 2 now

PowerShell, from the repo root, venv on. This is the only new skill this lesson asks you to perform:

.venv\Scripts\activate
uvicorn aiand_router.app:app --app-dir src --host 127.0.0.1 --port 8000

In a second terminal:

curl http://127.0.0.1:8000/health

Expect JSON with "ok": true and "aiand_key_set": true. Then one chat hop (router key, not the aiand key):

curl http://127.0.0.1:8000/v1/chat/completions `
  -H "Authorization: Bearer YOUR_ROUTER_KEY" `
  -H "Content-Type: application/json" `
  -d "{\"model\":\"router/auto\",\"messages\":[{\"role\":\"user\",\"content\":\"ping\"}]}"

Read X-Router-Model (the real aiand id) and X-Router-Path. Body model stays router/auto. OpenCode config is in the README: baseURL http://127.0.0.1:8000/v1.

Do not set TRAINED_PATH=trained on this rung. Without data/scorer.json you would only confirm scorer_down. That test already exists in pytest.
