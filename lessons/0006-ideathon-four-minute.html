Word-for-word spine (adapt to your voice)

1 · Problem & impact (0:00–0:45)

Coding agents don’t make one model call — they make dozens per session: discover, plan, edit, debug, summarize. Teams face a bad trade-off. Premium-only (always K3 / frontier) burns budget on trivial greps. Cheap-only (always Flash) fails multi-file refactors and tool-heavy debug. Who feels it? Engineering teams running OpenCode, Cursor, Claude Code against multi-model catalogs. Impact: measurable dollars per agent session — and fewer broken loops that waste human time.

2 · Solution & innovation (0:45–1:30)

We built aiand/auto — an OpenAI-compatible gateway. Point your agent at us with model: router/auto. Each hop, we filter ineligible models, then pick the cheapest model that still clears your quality bar.

What’s different: not a static “if phase=edit use model X” router. We train a tiny Scorer offline — a teacher labels difficulty and success priors; we measure gold on real aiand completions; we fit calibrated P(success). Live, that student runs in milliseconds — we do not call an LLM to decide the route. That is what AI enables: better picks without adding latency and cost to the routing itself.

3 · Demo (1:30–2:45) — one journey only

  1. User problem: “I need this agent step cheap but reliable.”
  2. User action: Playground (or OpenCode) sends one router/auto chat with a phase.
  3. AI / product process: Show response headers or UI: chosen model, reason/score, path.
  4. Useful result: Cut to dashboard — candidate mix + savings vs expensive baseline on that hop.

Skip login, keys page, and menus. Tabs pre-opened: playground + /routers/auto. Optional 5s: landing simulator as “what the product vision looks like” — then live hop. Prompt pack (phase + effort → Flash / Pro / K3): demo-prompts-ten.html (TRAINED_PATH=shadow for the ladder).

4 · Technical implementation (2:45–3:25)

Say the diagram out loud:

Agent → FastAPI gateway → Rules + Scorer → aiand API → result + JSONL log

  • Backend: FastAPI, OpenAI-compatible /v1/chat/completions
  • Frontend: Next.js landing, dashboard, playground
  • Data: 2000 train queries; gold/silver fit → data/scorer.json (not_spec_floors)
  • Proof of engineering: 213 tests; CI never spends credits; soft spend tracked locally

No framework laundry list. Feasibility > buzzwords.

5 · Potential & close (3:25–4:00)

Target users: teams and agent platforms that already speak OpenAI APIs. Adoption is a baseURL change — no harness rewrite. Scale: add models in YAML, retrain Scorer offline, shadow, then flip — same client forever. Next: promote trained after gates, SWE-bench Verified as the quality bar, managed SaaS / aiand partnership.

Close: “Agents will keep multiplying model calls. aiand/auto makes every hop cost-aware without rewriting the agent — and we can prove each pick in the log.”
