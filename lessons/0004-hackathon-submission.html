The Problem

Problem fit & real-world impact

AI coding agents run dozens of inference hops per session — discover, plan, edit, debug, summarize. Teams face a painful trade-off:

Premium-only baseline

  • Every step hits frontier models (Kimi K3, GLM-5, etc.)
  • Simple grep-and-summarize steps cost 10–40× more than needed
  • Budget caps stop agents mid-task

Cheap-only baseline

  • Flash on everything fails multi-file refactors
  • Tool-call accuracy drops on hard debug steps
  • Human time lost re-running failed agent loops
Who feels this? Engineering teams running OpenCode / Cursor agents against multi-model catalogs (aiand, OpenRouter, Bedrock). Spend is measurable in dollars per session; quality is measurable in tests-passed and patch-applied.

Our solution in one sentence

aiand/auto sits between the agent and aiand as an OpenAI-compatible gateway. Each request carries phase context (x-agent-phase) and effort tier (x-routing-effort). The router filters ineligible models, scores survivors, and picks the cheapest model that clears your quality bar.

Why We Beat Rule-Based Routers

Innovation & purposeful AI

Typical rule-based router

  • Hand-tuned if-else: if phase=edit → use Model X
  • Static benchmark scores (AA index) not measured on your agent trajectories
  • Same quality bar for a 1-line typo fix and a 12-file migration
  • Adding a new catalog model = retune dozens of thresholds by hand
  • Uncalibrated “confidence” — no link to actual task success rate

aiand/auto (rules today → trained tomorrow)

  • Per-request scoring — phase family, token count, tool schema → P(success)
  • Cheapest-above-bar — effort tiers (low/medium/high/max) set threshold + max-regret
  • Complexity bins — trivial / standard / hard / frontier from teacher labels
  • Calibrated probabilities — Platt scaling on gold completions; ECE target ≤ 0.03
  • <10 ms scorer — in-process features-only head; no embedding API on live hop
  • Graceful fallback — missing scorer → rules path with scorer_down

Three product pillars

PillarWhat it means
01 · Score every requestMulti-candidate P(success) in under 10 ms; no slow teacher on the hot path
02 · Clear your confidence bar4 effort tiers; regret-bounded pool; dynamic list-price ranking
03 · One universal endpointDrop-in /v1/chat/completions; headers expose chosen model, score, savings
AI used purposefully: Teacher models label offline training data; a tiny student classifier serves live traffic. We do not call an LLM on every routing decision — that would add latency and cost to the very problem we solve.
